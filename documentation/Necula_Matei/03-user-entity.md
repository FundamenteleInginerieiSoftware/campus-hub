## Part 1: In simple terms

Before anyone can log in, the app needs a place to remember its users. This PR builds that place.

1. **Created the `users` table** in the database: email, password (scrambled, never readable), full name, role, an "enabled" switch and the date the account was created.
2. **Defined the two roles:** `STUDENT` (books equipment, reports damage) and `ADMIN` (manages everything).
3. **Wrote the Java class that matches the table**, so the code can read and save users.
4. **Made emails case-insensitive:** `Ana@campus.test` and `ana@campus.test` are the same person. Emails are saved in lowercase, and the database refuses a second account with the same email.
5. **Added a way to look users up by email**, which login and registration will use in the next PR.
6. **Tested it on the real database:** a user can be found whatever capitals are typed, and a duplicate email is refused.

**Result:** the users table exists, and reservations, incidents and the other tables can now point to it. Next: register and login with a token (JWT).

### Table `users`

| Column | Type | Why |
|---|---|---|
| `id` | `BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` | Team PK rule; PostgreSQL picks the id (`GenerationType.IDENTITY`) |
| `email` | `VARCHAR(255) NOT NULL UNIQUE` | Login name. Stored lowercase, so a plain `UNIQUE` is enough |
| `password_hash` | `VARCHAR(255) NOT NULL` | BCrypt hash with its `{bcrypt}` prefix (delegating encoder, next PR) |
| `full_name` | `VARCHAR(100) NOT NULL` | Shown in notifications and admin pages |
| `role` | `VARCHAR(32) NOT NULL` | `@Enumerated(STRING)`: text, never the ordinal, so adding a role can't change old rows |
| `enabled` | `BOOLEAN NOT NULL` | Admin can block an account without deleting its reservations and reports |
| `created_at` | `TIMESTAMP NOT NULL` | `LocalDateTime`, campus local time (decision below) |

The table comes first in the FK order (users, assets → reservations → incident_reports → reassignment_log), so teammates' migrations that reference it need a later timestamp.

### Key choices

| Choice | Why |
|---|---|
| `Role` in `user.api`, not `user.domain` | The agreed `UserSummary(…, Role role)` lives in `user.api`, and other modules may import only `api`. Stefania's `CurrentUser` and Calin's admin checks can use it without breaking ArchUnit |
| Lowercase + trim in the `User` constructor | One place normalizes, so the `UNIQUE` column, register and login all agree. `Locale.ROOT` avoids locale surprises (e.g. Turkish `I`) |
| `findByEmailIgnoreCase` / `existsByEmailIgnoreCase` | Login and register don't have to remember to lowercase the input |
| `createdAt` passed into the constructor | The entity never calls `now()`. `AuthService` will pass `LocalDateTime.now(clock)` with Calin's shared `Clock`; tests pass a fixed time |
| `LocalDateTime` + `TIMESTAMP`, not `Instant` + `TIMESTAMPTZ` | Simplest: one time type in entities and JSON (ISO-8601 local, no offset). Hibernate's `validate` would reject an `Instant` field on a plain `TIMESTAMP` column. Recorded in `docs/decisions.md` §4 |
| `@Getter` only, `@NoArgsConstructor(access = PROTECTED)` | Hibernate needs the empty constructor; our code uses the full one. No setters yet: blocking a user will be a `disable()` method (state changes inside the entity) |
| `@Column(updatable = false)` on `createdAt` | Hibernate never rewrites it after the insert |

### Testing

| Command | Result |
|---|---|
| `cd backend && ./gradlew spotlessApply build` | BUILD SUCCESSFUL, 8 tests (2 new) |
| `UserRepositoryTest.findsUserByEmailIgnoringCase` | Saves `" Student1@Campus.test "`, finds it with `"STUDENT1@campus.test"`, stored as `student1@campus.test` |
| `UserRepositoryTest.rejectsSameEmailWithDifferentCase` | Second `saveAndFlush` with `ANA@campus.test` → `DataIntegrityViolationException` |
| `psql … campus_test -c '\d users'` | Columns as above, `users_email_key` UNIQUE constraint |

`@DataJpaTest` runs Flyway on the real `campus_test` database (`spring.test.database.replace: none`), so a mismatch between the migration and the entity fails in this test, not at runtime. `saveAndFlush` is needed in the failure test: plain `save` waits until commit, and the test transaction is rolled back before that.
