## Part 1: In simple terms

The **Reservation Module** is the core booking engine of the Campus Equipment & Incident Hub. It allows students and lab administrators to reserve equipment (oscilloscopes, 3D printers, specialized laptops, VR headsets) for specific time slots.

### Key Objectives
1. **Prevent double booking:** Two students must never be allowed to reserve the same equipment for overlapping time slots. Even if two students click "Book" at the exact same millisecond, database row-locking on the catalog asset ensures only one succeeds and the other gets an informative `409 Conflict` message (`RESERVATION_CONFLICT`).
2. **Enforce university booking rules:**
   - Bookings must be between 08:00 and 20:00 on the same weekday (Monday–Friday).
   - Slots must align to 30-minute intervals (`:00` or `:30`) with zero seconds.
   - Durations must be between 30 minutes and 4 hours.
   - A student can book up to 14 days in advance and have at most 2 active bookings simultaneously (admins bypass this limit).
   - Students can cancel a confirmed reservation at any point prior to its start time.
3. **Strict security & privacy (IDOR protection):** A student can only view and cancel their own reservations. If someone attempts to inspect another student's reservation by guessing an ID, the system responds with `404 Not Found` (`RESERVATION_NOT_FOUND`, never `403 Forbidden`) so attackers cannot determine which reservation IDs exist.
4. **Lifecycle state management:** Reservations move through explicit states (`CONFIRMED` $\to$ `CHECKED_OUT` $\to$ `RETURNED`, or `CANCELLED`, `FORCE_CANCELLED`, `OVERDUE`, `NO_SHOW`).

## Part 2: Technical details

### 1. Database Schema & Migration

**File:** `backend/src/main/resources/db/migration/V2026_10_25_1800__reservation_create_table.sql`

#### Table `reservations`
```sql
CREATE TABLE reservations (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    user_id BIGINT NOT NULL REFERENCES users(id),
    asset_id BIGINT NOT NULL REFERENCES assets(id),
    original_asset_id BIGINT REFERENCES assets(id),
    start_time TIMESTAMP NOT NULL,
    end_time TIMESTAMP NOT NULL,
    status VARCHAR(32) NOT NULL,
    created_at TIMESTAMP NOT NULL,
    checked_out_at TIMESTAMP,
    returned_at TIMESTAMP,
    cancelled_at TIMESTAMP,
    cancel_reason VARCHAR(255),
    version BIGINT NOT NULL DEFAULT 0,
    CONSTRAINT chk_reservation_time CHECK (end_time > start_time)
);
```

#### Columns & Purpose:
| Column | Type | Why |
|---|---|---|
| `id` | `BIGINT GENERATED BY DEFAULT AS IDENTITY` | Primary key adhering to team standard (`GenerationType.IDENTITY`). |
| `user_id` | `BIGINT NOT NULL REFERENCES users(id)` | Foreign key to the student who booked the equipment. |
| `asset_id` | `BIGINT NOT NULL REFERENCES assets(id)` | Foreign key to the currently assigned asset. |
| `original_asset_id` | `BIGINT REFERENCES assets(id)` | Preserves original asset ID when reassigned by the auto-reassignment engine. |
| `start_time` / `end_time` | `TIMESTAMP NOT NULL` | Booking interval in `Europe/Bucharest` local time. |
| `status` | `VARCHAR(32) NOT NULL` | `@Enumerated(EnumType.STRING)` storing reservation state. |
| `created_at` | `TIMESTAMP NOT NULL` | Creation timestamp from shared `Clock`. |
| `checked_out_at` / `returned_at` / `cancelled_at` | `TIMESTAMP` | Lifecycle audit timestamps. |
| `cancel_reason` | `VARCHAR(255)` | Reason for cancellation or force-cancellation. |
| `version` | `BIGINT NOT NULL DEFAULT 0` | `@Version` column providing optimistic locking for concurrent status updates. |

#### Indexes Created:
- `idx_reservations_asset_time ON reservations(asset_id, start_time, end_time)`: Optimizes overlap collision queries.
- `idx_reservations_user_status ON reservations(user_id, status)`: Accelerates counting active bookings per user and student history lookup.
- `idx_reservations_status_end ON reservations(status, end_time)`: Accelerates background jobs and active checkout lookups.

### 2. Domain Entity: `Reservation.java`

Located in `com.campus.reservation.domain`.

#### Entity Status Enum: `ReservationStatus`
```java
public enum ReservationStatus {
    CONFIRMED,
    CHECKED_OUT,
    RETURNED,
    CANCELLED,
    FORCE_CANCELLED,
    OVERDUE,
    NO_SHOW;

    public static final Set<ReservationStatus> ACTIVE_STATUSES =
            EnumSet.of(CONFIRMED, CHECKED_OUT, OVERDUE);
}
```

#### Lifecycle State Machine & Transition Methods:
The entity follows strict encapsulation: **no public setters**. State changes are performed only through explicit, validated domain methods:

1. **`checkOut(LocalDateTime now)`**: Moves `CONFIRMED` $\to$ `CHECKED_OUT`; sets `checkedOutAt`.
2. **`returnItem(LocalDateTime now)`**: Moves `CHECKED_OUT` or `OVERDUE` $\to$ `RETURNED`; sets `returnedAt`.
3. **`cancel(LocalDateTime now, String reason)`**: Moves `CONFIRMED` $\to$ `CANCELLED`; sets `cancelledAt` and `cancelReason`.
4. **`forceCancel(LocalDateTime now, String reason)`**: Moves `CONFIRMED` $\to$ `FORCE_CANCELLED`; idempotent if already force-cancelled.
5. **`markOverdue()`**: Moves `CHECKED_OUT` $\to$ `OVERDUE`.
6. **`markNoShow()`**: Moves `CONFIRMED` $\to$ `NO_SHOW`.
7. **`moveTo(Long newAssetId)`**: Updates `assetId` to `newAssetId` from `CONFIRMED` and sets `originalAssetId` if null.

All invalid transitions throw `InvalidStateTransitionException("INVALID_RESERVATION_STATUS_TRANSITION", message)`.

### 3. Repository: `ReservationRepository.java`

Located in `com.campus.reservation.repository`.

```java
@Query("""
    select count(r) > 0 from Reservation r
    where r.assetId = :assetId
      and r.status in :statuses
      and r.startTime < :end
      and r.endTime > :start
      and r.id <> :ignoreId
    """)
boolean existsOverlap(
        @Param("assetId") Long assetId,
        @Param("start") LocalDateTime start,
        @Param("end") LocalDateTime end,
        @Param("statuses") Collection<ReservationStatus> statuses,
        @Param("ignoreId") long ignoreId);
```

#### Overlap Formula:
Two half-open intervals $[S_1, E_1)$ and $[S_2, E_2)$ overlap **if and only if** $S_1 < E_2$ and $E_1 > S_2$.
- Abutting slots (e.g. 10:00–12:00 and 12:00–14:00) do NOT collide ($12:00 < 12:00$ is `false`).
- Active statuses tested: `CONFIRMED`, `CHECKED_OUT`, `OVERDUE`.

### 4. Service Layer: `ReservationService.java`

Located in `com.campus.reservation.service`. Implements `ReservationApi`.

#### A. `createReservation(CreateReservationRequest req)`
1. **Validations:** Opening hours (Mon–Fri 08:00–20:00 on same date), :00 or :30 alignment, 30m–4h duration, max 14 days in advance, not in past.
2. **Pessimistic Row Lock:** `catalogApi.lockForBooking(req.assetId())` acquires row lock in PostgreSQL FIRST.
3. **Operational Check:** `catalogApi.isBookable(req.assetId())` ensures status is `AVAILABLE`.
4. **Overlap Check:** `reservationRepository.existsOverlap(...)` prevents conflicting bookings.
5. **Quota Check:** `reservationRepository.countByUserIdAndStatusIn(...) >= 2` (students only; admins bypass).
6. **Persistence & Audit:** Saves `Reservation` and writes entry to `AuditService`.

#### B. `getMyReservations(ReservationStatus status, int page, int size)`
Returns `PageResponse<ReservationResponse>` for `currentUser.id()`.

#### C. `getById(Long id)`
Returns `ReservationResponse` or throws `404 NotFoundException("RESERVATION_NOT_FOUND", ...)` if not owned and not admin.

#### D. `cancelReservation(Long id)`
Validates ownership/admin and start time (`!now.isBefore(r.getStartTime())`), calls `r.cancel(now, "Cancelled by user")`, and writes audit record.

#### E. `moveToAsset(Long reservationId, Long newAssetId, String reason)`
Annotated with `@Transactional(noRollbackFor = SubstituteNoLongerFreeException.class)` so that candidate collisions in the auto-reassignment engine do not roll back caller transactions.

#### F. `findCurrentCheckout(Long assetId)`
Finds active checkout matching `CHECKED_OUT` or `OVERDUE`.
