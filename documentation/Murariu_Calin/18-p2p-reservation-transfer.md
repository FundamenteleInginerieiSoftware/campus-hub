## Part 1: In simple terms

Students often book laboratory equipment in advance for projects or coursework, but their schedules can change unexpectedly. Rather than simply cancelling a reservation and leaving equipment idle, students need a safe, collaborative way to transfer their reserved time slot directly to a classmate:

1. **Two-Way Agreement:**  
   Transferring an asset is not forced on anyone. The original student initiates a transfer request to a specific classmate. The reservation remains active and owned by the original student until the classmate explicitly accepts the transfer.
2. **Fairness and Quota Enforcement:**  
   A student cannot hoard equipment or accept transfers if they have already reached their quota of active reservations (maximum 2). The system checks and locks the recipient's quota during acceptance to ensure fair access for all campus students.
3. **No Double-Booking or Concurrent Exploits:**  
   Only future `CONFIRMED` reservations can be transferred. If an asset has already been checked out, or if the slot has already started, transfers are strictly disabled. Both parties receive notifications throughout the process.

## Part 2: Technical details

### 1. Database Schema & State Machine

The workflow is supported by a dedicated table `reservation_transfers`:

```sql
CREATE TABLE reservation_transfers (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    reservation_id BIGINT NOT NULL REFERENCES reservations(id) ON DELETE CASCADE,
    from_user_id BIGINT NOT NULL REFERENCES users(id),
    to_user_id BIGINT NOT NULL REFERENCES users(id),
    status VARCHAR(32) NOT NULL,
    created_at TIMESTAMP WITHOUT TIME ZONE NOT NULL,
    resolved_at TIMESTAMP WITHOUT TIME ZONE
);
```

#### Transfer State Machine:
- `PENDING`: Transfer initiated by the reservation owner.
- `ACCEPTED`: Recipient accepted the transfer; reservation ownership is transferred to `to_user_id`.
- `REJECTED`: Recipient declined the transfer; original reservation remains with `from_user_id`.
- `CANCELLED`: Original owner withdrew the transfer offer before recipient decision.

### 2. Concurrency & Business Rules

| Rule | Enforcement | HTTP Code / Exception |
|---|---|---|
| **Active Status** | Only `CONFIRMED` reservations can be transferred | `409 INVALID_RESERVATION_STATUS_TRANSITION` |
| **Future Start Time** | Reservation must be in the future (`now.isBefore(start)`) | `409 TRANSFER_NOT_ALLOWED` |
| **No Self-Transfer** | Cannot transfer reservation to own account | `409 CANNOT_TRANSFER_TO_SELF` |
| **Active Transfer Guard** | Only one active pending transfer per reservation | `409 TRANSFER_ALREADY_PENDING` |
| **Recipient Eligibility** | Recipient must exist and have an active student account | `404 USER_NOT_FOUND` |
| **Sender Account Guard** | Sender must remain active when transfer is accepted | `409 TRANSFER_NOT_ALLOWED` |
| **Ownership Integrity** | Reservation owner must still match transfer sender at acceptance time | `409 TRANSFER_NOT_ALLOWED` |
| **Pessimistic Row Lock** | `findByIdForUpdate(transferId)` prevents concurrent accept/cancel/reject race conditions | `SELECT ... FOR UPDATE` |
| **Advisory Quota Lock** | `pg_advisory_xact_lock(1, recipientId)` serializes concurrent acceptances and enforces the 2-active-reservations limit | `409 RESERVATION_LIMIT_REACHED` |
| **IDOR Protection** | Non-owners/non-recipients receive 404 rather than 403 | `404 RESERVATION_NOT_FOUND` / `404 TRANSFER_NOT_FOUND` |

### 3. REST Endpoints

| Method | Endpoint | Access | Purpose |
|---|---|---|---|
| `POST` | `/api/v1/reservations/{id}/transfers` | Owner / Admin | Initiate transfer offer to `recipientUserId` |
| `GET` | `/api/v1/reservations/transfers/pending` | Recipient | List incoming pending transfer offers for current user |
| `POST` | `/api/v1/reservations/transfers/{transferId}/accept` | Recipient / Admin | Accept incoming transfer and acquire booking |
| `POST` | `/api/v1/reservations/transfers/{transferId}/reject` | Recipient / Admin | Decline incoming transfer |
| `POST` | `/api/v1/reservations/transfers/{transferId}/cancel` | Sender / Admin | Cancel outgoing pending transfer |
