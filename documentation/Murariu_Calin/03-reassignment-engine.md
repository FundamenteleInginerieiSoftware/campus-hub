## Part 1: In simple terms

In a university lab, equipment breaks. A student might drop an oscilloscope probe, or a 3D printer nozzle might clog. When someone files an incident report stating that an asset is damaged, what happens to all the students who have reserved that same asset for tomorrow or next week?

Without an automated engine, lab staff would have to manually search through a schedule, locate every affected student, look for spare equipment, and send emails by hand.

### The Auto-Reassignment Engine
Our auto-reassignment engine handles this automatically:
1. When an asset is marked damaged, an event is fired (**Observer pattern**).
2. The engine wakes up after the incident transaction successfully commits (`AFTER_COMMIT`, `@Async`).
3. For every upcoming confirmed booking on the damaged asset (processed chronologically):
   - It searches for an identical spare asset (**Strategy pattern** - `SameModelStrategy`, preferring same lab room).
   - If not found, it falls back to an alternative asset from the same equipment category (**Strategy pattern** - `SameCategoryStrategy`, preferring same lab room).
   - If a substitute is found, the student's reservation is automatically migrated to the new equipment.
   - If no substitute is free across any strategy, the reservation is force-cancelled (`FORCE_CANCELLED`) so the student isn't left waiting at an empty lab desk.
4. Every action is permanently recorded in `reassignment_log` so lab staff can see what was moved, when, and why.
5. Affected students receive email/log notifications detailing the reassignment or cancellation.

### 3. Strategy Pattern: `SubstituteStrategy`

Located in `com.campus.reassignment.service`.

#### Interface: `SubstituteStrategy.java`
```java
public interface SubstituteStrategy {
    String name();
    Optional<AssetSummary> findSubstitute(ReservationSummary reservation, AssetSummary damaged);
}
```

#### Ordered Implementations:
1. **`SameModelStrategy.java` (`@Order(1)`):**
   - Retrieves candidates via `catalogApi.findAvailableByModel(damaged.model(), damaged.id())`.
   - **Hardening:** Filters strictly for `candidate.status() == AssetStatus.AVAILABLE`, excluding `RETIRED` or `UNDER_MAINTENANCE` units.
   - **Deterministic Ranking:** Prioritizes equipment in the same lab room (`damaged.labRoomId()`), with a secondary deterministic sort by lowest `id` (`thenComparing(AssetSummary::id)`).
   - Filters by `reservationApi.isAssetFree(candidate.id(), reservation.start(), reservation.end(), reservation.id())`.
2. **`SameCategoryStrategy.java` (`@Order(2)`):**
   - Retrieves candidates via `catalogApi.findAvailableByCategory(damaged.categoryId(), damaged.id())`.
   - **Hardening:** Filters strictly for `candidate.status() == AssetStatus.AVAILABLE`, excluding `RETIRED` or `UNDER_MAINTENANCE` units.
   - **Deterministic Ranking:** Prioritizes same lab room, then by lowest `id`, and filters by `reservationApi.isAssetFree(...)`.

### 4. Reassignment Service: `ReassignmentService.java` & `ReassignmentBookingProcessor.java`

Located in `com.campus.reassignment.service`.

#### Orchestrator & Per-Booking Isolation
```java
// ReassignmentService.java (orchestrator - non-transactional)
public void handle(AssetDamagedEvent event)

// ReassignmentBookingProcessor.java (per-booking worker)
@Transactional(propagation = Propagation.REQUIRES_NEW)
public Optional<ReassignmentExecutionResult> processSingleBooking(
        AssetDamagedEvent event, ReservationSummary booking, AssetSummary damaged)
```

#### Why `Propagation.REQUIRES_NEW` per booking?
- **Transaction Isolation:** Reassignment runs in its own distinct transactions after incident creation commits (`AFTER_COMMIT`).
- **Bug #112 Fix (Per-booking boundary):** Previously, all bookings were processed in one single `REQUIRES_NEW` transaction. If one reservation had a concurrent update (e.g. cancelled by the student in the UI or swept by the no-show job), the stale entity in Hibernate caused an optimistic locking failure on commit that rolled back the entire batch, after emails were already sent. With `ReassignmentBookingProcessor` having `@Transactional(propagation = Propagation.REQUIRES_NEW)`, each booking commits independently, and notifications are sent only post-commit.
- **Rollback Resilience:** `ReservationService.moveToAsset` is configured with `noRollbackFor = SubstituteNoLongerFreeException.class`, ensuring that if a candidate asset becomes unavailable between selection and move, the transaction is not poisoned and cleanly falls back to the next strategy.

### 5. Observer Pattern: `LocalAssetDamagedListener.java`

Located in `com.campus.reassignment.service`.

#### Event: `AssetDamagedEvent`
Published by the Incident module when equipment damage is confirmed:
```java
public record AssetDamagedEvent(
    Long incidentId,
    Long assetId,
    Long reportedById,
    Instant occurredAt
) {}
```

#### Listener Implementation:
```java
@Component
@ConditionalOnProperty(name = "app.messaging.sqs.enabled", havingValue = "false", matchIfMissing = true)
@RequiredArgsConstructor
class LocalAssetDamagedListener {

    private final ReassignmentService reassignmentService;

    @Async
    @TransactionalEventListener(phase = TransactionPhase.AFTER_COMMIT)
    public void on(AssetDamagedEvent event) {
        reassignmentService.handle(event);
    }
}
```

- `@TransactionalEventListener(phase = AFTER_COMMIT)` guarantees no execution if the incident transaction rolls back.
- `@Async` ensures reassignment executes in the background without adding latency to the student's incident submission.
- `@ConditionalOnProperty`: In dev and monolith prod, runs in-memory; when SQS is enabled (`app.messaging.sqs.enabled=true`), turns off local listener in favor of Matei's SQS bridge.

This prevents test slots from expiring after calendar dates pass, ensuring tests pass deterministically in CI.
