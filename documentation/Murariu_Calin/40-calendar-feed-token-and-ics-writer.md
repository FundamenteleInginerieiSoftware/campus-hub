## Part 1: In simple terms

Students want their lab bookings to show up automatically inside Google Calendar, Apple Calendar, or Outlook. Those calendar apps cannot log in with a Campus Hub username and password or refresh short-lived JWTs—instead, they poll a **secret subscription address** (just like Google Calendar's own "Secret address in iCal format").

This change builds the two foundations for that feature:
1. **Secret link management (`calendar_feeds` + settings endpoints):** A logged-in student can check if a link is active (`GET`), create or replace their link (`POST`), or turn it off (`DELETE`). Just like an API key, the full address is shown **only once** at creation time. The server stores only a one-way cryptographic fingerprint (SHA-256 hash), so even a database dump cannot expose working calendar links. Creating a new link replaces the old fingerprint in place, immediately cutting off any leaked URL.
2. **iCalendar file writer (`IcsWriter`):** A small, standalone formatter that turns booking records into standard `.ics` (RFC 5545) text—handling strict `CRLF` line endings, escaping commas/semicolons/backslashes/newlines, converting campus times (`Europe/Bucharest` winter UTC+2 / summer UTC+3) to UTC `Z` timestamps, and wrapping lines at 75 UTF-8 bytes without splitting Romanian characters like `ș` or `ă`.

## Part 2: Technical details

### 1. Database Migration & Entity (`calendar_feeds`)
- **Migration:** `backend/src/main/resources/db/migration/V2026_11_16_2205__reservation_create_calendar_feeds.sql`
  - `id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`
  - `user_id BIGINT NOT NULL UNIQUE REFERENCES users (id)` — enforces at most one feed row per user; regenerating replaces the hash in the same row.
  - `token_hash VARCHAR(64) NOT NULL UNIQUE` — 64-character lowercase SHA-256 hex digest with a unique index for single-lookup resolution.
  - `created_at TIMESTAMP NOT NULL` — truncated to whole seconds.
- **Entity (`CalendarFeed`):** `@Getter`, `@NoArgsConstructor(access = PROTECTED)`, no setters; state updates happen exclusively via `replaceToken(String tokenHash, LocalDateTime now)` (truncating `createdAt` to `ChronoUnit.SECONDS`).
- **Repository (`CalendarFeedRepository`):** `findByUserId(Long)`, `findByTokenHash(String)`, `deleteByUserId(Long)`.

### 2. Token Service & Settings API
- **`CalendarTokenService`** (`com.campus.reservation.service`):
  - **Token format:** 32 random bytes from `SecureRandom` encoded with `Base64.getUrlEncoder().withoutPadding()` → 43-character `[A-Za-z0-9_-]{43}` token.
  - **Why SHA-256 instead of BCrypt:** A 256-bit random token has full cryptographic entropy and cannot be brute-forced; deterministic SHA-256 lets public feed lookups find the matching row in one indexed DB query (salted BCrypt cannot be queried by hash).
  - **`status()` (`@Transactional(readOnly = true)`):** returns `CalendarFeedStatusResponse(boolean enabled)` for `currentUser.id()`.
  - **`create()` (`@Transactional`):** creates or updates the user's `CalendarFeed` row, records audit action `CALENDAR_FEED_CREATED` (`entityType = "USER"`, `entityId = userId`), and returns `CalendarFeedCreatedResponse("/api/v1/calendar/" + token + ".ics")`.
  - **`revoke()` (`@Transactional`):** deletes the user's row if present and records `CALENDAR_FEED_REVOKED` only when a row actually existed (idempotent when absent).
  - **`findActiveUserId(String token)` (`@Transactional(readOnly = true)`):** validates `[A-Za-z0-9_-]{43}` **before** hashing or touching the DB (blocking garbage/oversized inputs), hashes with `hash(token)`, looks up `CalendarFeed`, and checks `UserApi.findActiveRole(userId).isPresent()` (Matei's #128 rule so disabled/deleted users lose feed access immediately).
- **`CalendarFeedSettingsController`** (`/api/v1/reservations/me/calendar-feed`):
  - `GET` → `200 CalendarFeedStatusResponse`
  - `POST` → `201 CalendarFeedCreatedResponse`
  - `DELETE` → `204 No Content`
  - Annotated with `@Tag(name = "Calendar feed")`, `@Operation` summaries, `@ApiResponses` (200/201/204 + 401), and explicit `produces = MediaType.APPLICATION_JSON_VALUE` on JSON endpoints to satisfy `OpenApiDocsIT`.

### 3. Pure iCalendar Serializer (`IcsWriter` & `CalendarEvent`)
- **`CalendarEvent(String uid, Instant start, Instant end, String summary, String description)`** in `com.campus.reservation.service`.
- **`IcsWriter`** (pure Java, zero Spring dependencies):
  - `write(String calendarName, List<CalendarEvent> events, Instant now)`: emits `VCALENDAR` (`VERSION:2.0`, `PRODID:-//Campus Hub//Reservations//EN`, `CALSCALE:GREGORIAN`, `METHOD:PUBLISH`, `X-WR-CALNAME`) and one `VEVENT` per event with UTC `yyyyMMdd'T'HHmmss'Z'` timestamps and CRLF (`\r\n`) line endings.
  - `escape(String text)`: escapes `\`, `;`, `,` and normalizes `\r\n`, `\r`, `\n` to literal `\n`.
  - `fold(String line)`: iterates Unicode code points and accumulates UTF-8 byte lengths, splitting lines at ≤ 75 bytes (continuation lines begin with `" "` taking 1 byte + up to 74 payload bytes) so multi-byte UTF-8 letters (`ș`, `ț`, `ă`) are never cut in half.
