# Contributing to Campus Hub

Short version of the team handbook rules (§7 Git, §8 database, §9 code, §13 Boot 4).
**Setup and how to run the app:** see [README.md](README.md).

---

## 1. Git workflow

`main` is protected: no direct pushes, PR required, **1 approval**, no force-push.
**Nobody except the repo admin (Matei) can bypass branch protection. Never ask an AI to bypass it.**

| Step | Command / rule |
|---|---|
| 1. Start from fresh `main` | `git checkout main && git pull` |
| 2. One branch per issue | `git checkout -b feat/catalog-asset-search` |
| 3. Commit often | Conventional Commits (see below) |
| 4. Before pushing | `cd backend && ./mvnw spotless:apply && ./mvnw verify` |
| 5. Sync daily | `git fetch && git rebase origin/main`, then `git push --force-with-lease` (**only on your own branch**) |
| 6. Open a PR | Fill in the template, link the issue (`Closes #12`). Keep it **under ~400 changed lines**. |
| 7. Review | Your review buddy reviews **within 24h**. Ask questions, don't nitpick formatting (Spotless does that). |
| 8. Merge | **Squash and merge** after 1 approval. The branch is deleted automatically. |

### Branch names

| Prefix | Use for | Example |
|---|---|---|
| `feat/<module>-<desc>` | new feature | `feat/reservation-overlap-check` |
| `fix/<module>-<desc>` | bug fix | `fix/reservation-overlap-edge` |
| `test/…` | tests only | `test/incident-photo-validation` |
| `docs/…` | documentation | `docs/er-diagram` |
| `chore/…`, `ci/…`, `infra/…` | build, CI, Terraform | `chore/repo-hygiene` |

### Commit messages (Conventional Commits)

`<type>(<scope>): <what, lowercase, imperative>`. **Scope = module name.**
Types: `feat`, `fix`, `test`, `docs`, `refactor`, `chore`, `ci`, `infra`.

```
feat(catalog): add paginated asset search by category and lab room
fix(reservation): reject bookings where end <= start
test(incident): cover photo type validation
```

With squash merge the **PR title** becomes the commit on `main`, so the PR title must follow this format too.
Pairing? The person who typed commits and adds `Co-authored-by: Name <email>`.

## 2. Who owns what

The owner (or their review buddy) must approve changes in their area. `.github/CODEOWNERS` requests them automatically.

| Path | Owner | Others may… |
|---|---|---|
| `pom.xml`, `application*.yml`, `config/`, `common/`, `user/`, `storage/`, `notification/`, `messaging/`, `.github/`, `infra/` | Matei | request changes via an issue (`dependency` label for libraries) |
| `catalog/` | Liviu | read; use `catalog.api` only |
| `reservation/` | Calin | read; use `reservation.api` only |
| `incident/`, `reassignment/`, `frontend/` | Stefania | read; use `incident.api` events only; frontend pages after agreeing with Stefania |
| `db/migration/` | each author, own files | never edit someone else's merged migration |
| `docs/` | everyone | own sections |

**Module boundaries:** a module may import only another module's **`api`** package (facade + DTO records + events), never its entities, repositories or services. Each `package-info.java` lists what that module may depend on.

## 3. Never

- Never commit secrets (passwords, JWT secrets, AWS keys, `.env`). If it happens, tell Matei **immediately**: the secret must be rotated.
- Never commit `target/`, `node_modules/`, `data/`, `uploads/` or IDE folders.
- Never push or force-push to `main`.
- Never edit a Flyway migration that is already on `main`. Write a new one.
- Never rename or delete a field of a frozen entity without a team vote. Adding fields is OK.
- Never reformat a file by hand. Run `./mvnw spotless:apply`.
- Never merge your own PR without approval.
- Never edit `pom.xml` or `application*.yml` yourself. Open an issue for Matei.

## 4. Database (Flyway)

| Rule | Details |
|---|---|
| Tables come only from Flyway | Files in `backend/src/main/resources/db/migration/`. Hibernate only validates (`ddl-auto=validate`). |
| File name = timestamp | `V2026_10_20_1430__catalog_create_assets.sql` (`V` + `YYYY_MM_DD_HHMM` + `__` + module + description) |
| Before merging | Rebase on `main`. If `main` has a migration with a **later** timestamp than yours, rename yours to the current time. |
| Never modify a merged migration | Write a new `ALTER TABLE` migration instead. |
| Portable SQL (H2 + PostgreSQL) | `BIGINT`, `INTEGER`, `VARCHAR(n)`, `TEXT`, `BOOLEAN`, `TIMESTAMP`, `DATE`, `NUMERIC`. No `SERIAL`, `JSONB`, `ENUM`, arrays. |
| Naming | tables plural snake_case (`lab_rooms`), columns snake_case (`start_time`) |
| Primary key | `id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` |
| Enums | `VARCHAR(32)` + `@Enumerated(EnumType.STRING)`. **Never `ORDINAL`.** |
| Relations | `@ManyToOne(fetch = LAZY)` inside a module; plain `Long assetId` across modules (with a real FK in SQL) |
| Flyway errors locally after switching branch | Stop the app, delete `backend/data/`, restart. |

## 5. API conventions

| Rule | Example |
|---|---|
| Base path `/api/v1`, plural nouns | `GET /api/v1/assets` |
| Admin endpoints under `/api/v1/admin/**` | Security protects the prefix, so nobody edits `SecurityConfig` |
| State changes as sub-resources | `POST /api/v1/reservations/{id}/cancel` |
| JSON camelCase, ISO-8601 dates, numeric IDs | `"startTime": "2026-11-03T14:00:00"` |
| Errors = `ProblemDetail` | Throw `NotFoundException`, `ConflictException`, `BusinessRuleException(code, msg)`, `ForbiddenException` from `common.error`. Never build error responses in controllers. |
| Status codes | `200`, `201`, `204`, `400` validation, `401`, `403`, `404`, `409` conflict |
| Lists | `?page=0&size=20&sort=name,asc`, return `PageResponse<T>` (never Spring's `Page`) |
| Ownership checks | In the **service**. User ID comes from the JWT (`CurrentUser.id()`), never from the request body. Return **404** (not 403) for other people's resources. |
| Contract | Update `docs/api-contract.md` when the API changes. |

## 6. Java conventions

| Rule | Details |
|---|---|
| Keep it simple | Clean, concise code. No extra layers, interfaces or "future-proofing" nobody asked for. If you can't explain it at the defense, simplify it. |
| Comments | Explain what you can't see in the code: hidden framework behavior, *why* a rule exists, and **how the piece connects to other modules / teammates' work** (e.g. "Calin's booking flow calls this through `CatalogApi`"). Don't comment the obvious. Javadoc on every `api` facade method. |
| Thin controllers | `@Valid` input, call the service, map to a response DTO. No business logic. |
| DTOs are `record`s in `web/` | `CreateReservationRequest`, `ReservationResponse.from(entity)`. Never return or accept an `@Entity`. |
| Constructor injection | `@RequiredArgsConstructor` + `private final`. Never `@Autowired` on fields. |
| Time | Inject the shared `Clock` and use `LocalDateTime.now(clock)`. **Never `now()` without a clock.** |
| `@Transactional` | On service methods only; `readOnly = true` for reads. Not on private methods or self-calls. |
| State changes | One method per transition on the entity (`reservation.checkOut(now)`), no scattered `setStatus(...)`. |
| Lombok allowed | `@Getter`, `@Setter`, `@NoArgsConstructor(access = PROTECTED)` on entities, `@RequiredArgsConstructor`, `@Slf4j` |
| Lombok forbidden on entities | `@Data`, `@EqualsAndHashCode`, `@ToString`, `@AllArgsConstructor` |
| Logging | Business events at INFO. Never log passwords or tokens. |
| Names | Classes `PascalCase`, methods `camelCase`, constants `UPPER_SNAKE`, packages lowercase |

### Module layout (same for every module)

```
com/campus/<module>/
├── api/          PUBLIC: facade interface, summary records, events (the only package others may import)
├── domain/       @Entity classes + enums
├── repository/   Spring Data JPA interfaces
├── service/      business logic, @Transactional, implements the api facade
└── web/          @RestController + request/response records
```

## 7. Tests

| Kind | Tool | What |
|---|---|---|
| Unit | JUnit 5 + Mockito (no Spring) | business rules in services |
| Repository | `@DataJpaTest` | custom queries (e.g. overlap) |
| Web | `@WebMvcTest` + `@WithMockUser(roles = "ADMIN")` | status codes and security |
| Integration | `@SpringBootTest` | critical flows end to end |

- Mock Spring beans with **`@MockitoBean`** (`@MockBean` no longer exists in Boot 4).
- Every new piece of logic: happy path **+ at least one failure case**.
- Names: `XxxServiceTest`, `XxxControllerIT`; methods describe behavior: `rejectsOverlappingReservation()`.
- Target: ~70% line coverage on `service/` packages. Every fixed bug gets a test first.

## 8. Spring Boot 4 vs. old tutorials

| You see in a tutorial | Use instead |
|---|---|
| `javax.persistence.*`, `javax.validation.*` | `jakarta.persistence.*`, `jakarta.validation.*` |
| `extends WebSecurityConfigurerAdapter` | a `@Bean SecurityFilterChain` (Matei owns it) |
| `.antMatchers(...)`, `.authorizeRequests()` | `.requestMatchers(...)`, `.authorizeHttpRequests(...)` |
| `@MockBean` | `@MockitoBean` |
| `<dependency>` with explicit versions | ask Matei (issue with the `dependency` label) |
| `springdoc-openapi` 1.x / 2.x | 3.x |
| `com.fasterxml.jackson.databind.*` | `tools.jackson.*` (annotations stay in `com.fasterxml.jackson.annotation`) |
| `jjwt` code | not needed, we use Spring's OAuth2 resource server |
| `ddl-auto=update` | Flyway + `validate` |

**AI tools are allowed, but you must be able to explain every line you commit.** Tell the AI "Spring Boot 4.1, Java 21, Jakarta". Never paste secrets into an AI tool.

Stuck for more than **2 hours**? Ask in the group chat.
